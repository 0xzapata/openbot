OpenBot · content manager · v1

Write once, publish to six networks

OpenBot becomes the place you write once and publish to six networks, with Herald filling the queue. The queue is the home screen, not the composer.

Spec status: awaiting user approval. No code exists. Design: Loupe. Build: Forge. Written companion: docs/content-manager/ux.md. Screens use example data and the dark theme.

1 · Spec

What v1 does

Flow

  1. Herald, or you, creates a post with per-network variants.
  2. The post lands in the queue as pending.
  3. You approve once. Skipping a network is one click.
  4. You pick one local time for all six.
  5. At that time each network publishes independently.
  6. A failure shows failed with a Retry button. Nothing retries by itself.

Data model: three tables

content_accounts one connected account per network: handle, encrypted tokens, scopes, expiry, status.

content_posts approval_state (none, pending, approved), scheduled_for, timezone.

content_variants one per post and account: body, title, media, status, attempt, pending_data, external_post_id, error.

UNIQUE(post_id, account_id). The post has no stored status: one pure function derives it from its variants. No delivery table: one shared time makes a delivery 1:1 with a variant.

Endpoints: ten

content:list-accountscontent:list-posts content:begin-connectcontent:create-post content:disconnect-accountcontent:update-post content:schedule-postcontent:publish-now content:delete-postcontent:calendar content:changedevent

Local only. No scopedRequest, no Team API capability in v1. The publisher reuses the single RoutineTimer.

6 · Open questions for Forge

Decide before step 4

  1. Unschedule and unskip. The ten endpoints have no unschedule-post. Can update-post move a variant from queued to draft, and from skipped back?
  2. Disconnect with scheduled posts. This design keeps them queued; they fail at publish time with "Sign in to {network} again".
  3. Character count. X counts a link as 23 characters. Who owns the per-network count function?
  4. Herald's time. Can an agent set scheduled_for on a pending post? Approve-and-queue assumes yes.
  5. design.md and the spec differ on deliveries. This design follows the spec: one variant is one delivery.

Needs with no existing component

  1. Network chip (ContentNetworkChip): toggle plus five states. Built only from existing parts.
  2. Character count (ContentCharacterCount): thin wrapper on RadialProgress and Text.
  3. Media drop field (ContentMediaField): no file drop zone exists in the app.
  4. Empty state (ContentEmpty): no generic empty state exists.
  5. Post calendar (PostCalendar): already planned in design.md; it copies the routine planner.
  6. YouTube mark: one path added to brand-marks.tsx.

Each new shared component needs a Storybook story when it lands. Copy the token values of .tasks-page-section* and .routine-planner-* into content.css; do not import a feature's CSS from another feature.
